# 大模型协作与纠错摘要

本文件为基于当前会话和已保存源码/测试报告整理的摘要，不是完整逐字原始会话。真实摘录另见verified_excerpts.md；建议模型/UI队友补其侧原始提示词、回答与修正。没有导出任何其他聊天或账户数据。

| 阶段 | AI参与 | 人工/实际证据 | 纠正或边界 |
|---|---|---|---|
| 平台与划分 | 分析PYNQ-ZU与模型，明确PS/PL划分 | 板卡资料、PS参数、原模型SHA | 实际为UltraScale+，非早期Zynq-7000描述 |
| HDMI与PL | 提醒完整bitstream不能与BaseOverlay先后叠加保留 | 用户改为笔记本HDMI，当前工程不含板卡HDMI | 不再以HDMI许可阻碍卷积独立验证 |
| HLS/DMA | 导出两块模型、参数、AXIS包和驻留权重 | C/RTL/驱动、IP、bit/hwh、post-route报告 | 原厂全设计cosim未完成，如实区分功能primitive绑定 |
| PW16 | 增加PW输入并行度、生成独立版本 | v1/v2独立板测7.54到6.54ms | 局部提速不算整机倍数 |
| PS引擎/线程 | ORT替换CPU部分、比较线程和流水线 | 第三/四版原始同图板测 | 依据数据选serial_cv1_t3，不因版本新就采用流水线 |
| 量化探索 | 尝试INT8候选 | 本地坐标/置信度偏差超预设界限 | 未纳入最终部署，不降低阈值强行通过 |
| Notebook哈希 | 最初误将输出可变文件纳入校验 | 用户真实报错、fix_v3_notebook_check.py与本地复现 | 改为Notebook可变，其余关键文件仍校验 |
| 运行库恢复 | 原解压中断后vendor无完成标记 | 用户真实报错、repair_v4_runtime.py、恢复验证 | 暂存完整校验再启用，备份部分目录、不改系统包 |
| 最终核对 | 匹配日志会话、FPGA计数和订单 | 714比较、171硬件分类、23动作、33元落盘 | 正式报告写35.7%协同收益，不夸大为硬件核提升 |

工作流：用户给模型/板卡/日志 → AI构建候选与独立校验 → 本机测试通过 → 用户板上运行 → AI按同图、同模型与原始日志比较 → 保留有收益配置并冻结。流程没有远程代替用户上板，也没有自动发布仓库、付款或向餐厅发送订单。
