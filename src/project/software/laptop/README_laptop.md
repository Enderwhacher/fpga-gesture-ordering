# 笔记本点餐与显示

菜单保留队友 v2 的汉堡 18 元、可乐 6 元、薯条 9 元。笔记本从板卡读取识别结果，执行原有点餐逻辑，并在本机浏览器显示。显示器接笔记本 HDMI。

## 启动

1. 将 `gesture_order_laptop_v1.zip` 解压到一个文件夹，**先解压再运行**。
2. 保持笔记本通过网线连接板卡，确认板卡 Notebook 已显示 `ORDER_BOARD_SERVER_READY port=8765`。旧摄像头/板卡 HDMI 点餐程序应已停止。
3. 在解压后的 `gesture_order_laptop_v1` 文件夹双击 **`start_laptop.bat`**。当前这台电脑会优先使用 `D:\hand\.venv\Scripts\python.exe`；其他电脑可使用已安装依赖的 Python 3.10+。
4. 浏览器自动打开 `http://127.0.0.1:8080/`。若未自动打开，手动输入该地址。保持启动时出现的命令窗口运行。
5. 页面显示“识别已连接”后，将浏览器移到笔记本 HDMI 连接的显示器上，点击“全屏显示”或按 F11。Windows 多屏可用 Win+P 选择复制/扩展。

如果双击后提示缺少 `cv2` 或 `numpy`，使用准备运行本程序的那个 Python 安装：

```text
python -m pip install -r requirements-laptop.txt
```

当前工作电脑已具备所需依赖。本程序不要求笔记本安装 PYNQ 或 FPGA 工具。OpenCV 仅用于画面绘制和编码，浏览器负责显示，因此可使用 headless 版本。

如板卡 IP 改变，在该文件夹终端中运行：

```text
python laptop_app.py --board http://板卡IP:8765 --open-browser
```

## 先走通一次订单

每次做动作后，把手移出摄像头，等底部显示 READY，再进行下一步；只换手势不会解锁。

1. 张手并保持：进入菜单。
2. 点赞并保持：添加一份汉堡。
3. 张手：选中可乐；点赞：添加可乐。
4. 张手：选中薯条；点赞：添加薯条。
5. 握拳：进入订单核对，检查总计 33 元。
6. 再次点赞：确认保存模拟订单。此时才显示完成页面。

核对页张手切换行、握拳减一、V 返回菜单。菜单页 V 先进入退出确认，点赞才丢弃购物车，V 取消退出。每道菜最多 9 份。

正式运行时不要点击 `start_demo.bat`。该入口用于脱离板卡检查菜单，明确标注“离线演练：未使用摄像头或 FPGA”，不能用来证明硬件识别。演练中点击手势后等待动作完成，再点击“移开手”，等 READY。

## 如何确认走了 FPGA

展开页面底部“查看运行状态”，应显示 `CPU + FPGA`。先把完整手部放入摄像头，再观察 **FPGA 完成次数持续增加**。该数值来自板卡分类器成功执行完整 FPGA 路径后的计数；无手时跳过分类，计数不增加是正常现象。

“识别速度”是板卡实际完成的识别次数/秒，包含手掌检测及有手时的分类；画面显示帧率单独统计。侧栏 `D / C ms` 分别为 CPU 手掌检测和完整分类耗时，`FPGA call ms` 包含打包、DMA、硬件运算和输出复制校验，不能解释为纯硬件运算耗时。

单独分类缓存方案此前板上 20 轮中位数为 CPU 137.567 ms、含 FPGA 路径 136.830 ms，约低 0.54%，幅度很小；这不是新整机系统的延迟，不能据此宣称明显的端到端提速。当前目标是先让真实硬件路径与点餐界面完整运行。

## 断线与结果过期

同一帧序号只参与一次手势确认。服务会话变化、断线、过期结果都会停止新操作，购物车保留。恢复后先移开手，等待连续的真实无手结果重新解锁。

板卡与笔记本不需要同步墙上时间。板卡发送“从采集至今经过多久”，笔记本再加上请求用时作保守时效判断；不直接比较两台机器的 monotonic 或日期时间。说明参考 [Python monotonic 文档](https://docs.python.org/3.10/library/time.html#time.monotonic)；实现见 `remote_client.py`。

右上角等待板卡时，请先检查板卡服务是否仍在运行。不要重新启动旧的板卡 HDMI 程序。若页面显示“本机程序已停止”，重新运行本机启动脚本并刷新网页。命令窗口如有报错，请复制完整报错再关闭。

## 停止与结果文件

在启动程序的命令窗口按 Ctrl+C，等待打印 `LAPTOP_LOG`。浏览器关闭不会停止程序；请用 Ctrl+C 正常停止。

`logs/orders/` 保存模拟订单 JSON，包含菜品、数量、总价、`simulated: true`、`paid: false`。`logs/laptop_session_*.json` 保存会话状态、真实后端身份、成功 FPGA 分类计数及动作记录。不会付款或发送到餐厅。

请把本机 `logs` 文件夹压缩后，与板卡 Notebook 生成的 `gesture_order_remote_board_results.zip` 一起发回。首次实际联调需要确认：图像方向正确、4 类动作可用、FPGA 计数增加、保持手势不重复加菜、核对后才能生成一次订单，以及拔网线后不再执行动作。

## 当前验证范围

本机已验证原有业务规则、结果去重/时效、异常清理、HTTP 接口、相机预览传输与离线演练。HTTP 检查使用测试摄像头和测试后端；本次新主程序尚未在你的真实摄像头与 FPGA 上完成整机联调。此前计算比特流的板上数值校验已通过，两个验证范围分别记录。
