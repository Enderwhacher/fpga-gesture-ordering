# 有限体积的项目交接

先确定交付是代码提交包、可部署包还是完整构建归档。用户要求200MB时用200,000,000字节作为保守上限；RAR必须是真正的RAR，不将ZIP改后缀。

1. 以用户确认的版本清单为基线，列运行代码、HLS/RTL、Tcl/BD/IP、bit/hwh、模型/runtime/meta、参数、向量、依赖和原始证据的对应关系。
2. 保留已验证原包，另建工作副本。精简可排除构建缓存、重复安装档、演示媒体，但先检查调用方，不删除唯一源文件、IP元数据或模型参数。
3. 保存排除清单及来源哈希。源工程摘录无routed DCP时明确说明需重建；现有bit可部署不等于摘录源码已重新综合。
4. 旧安装器若依赖被排除的ZIP，更新代码包部署说明，不能继续称“一键安装”。记录未包含的原始训练数据、镜像与特定运行库快照。
5. 给出独立启动入口、目录映射、依赖边界、停止步骤与验证输出。Notebook可变输出不和不可变模型/源码混为一个放行开关。
6. 更新当前包的project_manifest，但保持原应用/硬件的内部清单和证据不变。不要篡改哈希绕过真实模型/硬件不一致。
7. 压缩后检查真实格式、字节大小、CRC，并实际解压后逐文件核对SHA。长生成IP路径在Windows应使用较短解压目录或支持长路径的工具。
