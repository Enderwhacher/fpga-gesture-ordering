# 从瓶颈选择 FPGA 子图

输入至少应有：模型/预处理哈希、固定输入、各阶段实测、目标器件资源、候选边界张量和数值基线。缺计时则先给测量方案，不以 MAC 占比代替耗时占比。

1. 拆分采集、预处理、检测、分类、传输、后处理及显示；优先分析真实瓶颈。核快但总体不快时不要直接扩大并行度。
2. 对候选记录计算量、输入输出字节、权重字节、调用次数、CPU剩余部分和资源上限。连续子图融合可以减少中间往返，但片上缓存和时序也需验证。
3. 建立 CPU→PL→CPU 的边界契约，保存切分前后软件结果。残差、SE、激活、BN折叠等必须保持语义，不能只实现看起来最重的卷积便称完整子图等价。
4. 分开初始化加载和每次 RUN 成本；若权重驻留，确认重载/Overlay 切换后的生命周期。两个参数 bank 不等于跨帧双缓冲。
5. 估算 T_new = T_unchanged + T_PL + T_transfer + T_extra。若可加速比例为实测 p，理想无限核速度且无新增开销的上限为 1/(1-p)；不是实际承诺。
6. HLS C 与 RTL检查、实现资源/时序、真实板测逐层推进；保留失败候选。相同模型和参数下比较完整网络及整帧结果，数值通过再讨论收益。

## 本项目案例与迁移边界

当前 PL 为 MobileNetV3 features.5+features.6，边界 FP32 1×40×28×28；其 MAC 占分类 Conv 约9.24%，不是检测加分类耗时占比。CPU手掌检测仍在 PS。新模型/器件需重新分析，不能照搬尺寸或并行因子。
