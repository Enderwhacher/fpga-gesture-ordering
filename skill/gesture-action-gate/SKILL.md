# 从识别结果到可靠动作

分类器输出标签，动作门控负责“何时算一次”。不要用平滑标签替代显式状态机，也不要把预览帧直接当作新的识别结果。

1. 明确三层：分类观察、GestureGate事件、业务页面/订单。先测试门控和业务纯逻辑，再接摄像头。
2. 相同session下仅接受新seq、合法且未过期的观察。保持时间用源观察时间，重复HTTP响应不能累加确认次数。
3. 连续新结果满足类别、分数、最少次数及保持时长后触发一次并锁定。保持同一手势或直接换另一手势均不能绕过释放。
4. 解锁需要明确detected=false的多次新观察达到释放时长。低分类分数、未知标签、断线、服务重启或过期都不是“真实移开手”。
5. 同一动作在不同页面意义不同。写出菜单/核对/退出确认的映射；金额用整数分，保存失败必须反馈，不应把失败订单视为完成。
6. 修改阈值时同时检查漏触发、重复触发及动作总延迟。阈值是项目配置，不是模型准确率保证。

## 验收场景

- 长时间保持只触发一次；两个重复seq不满足“两个新结果”。
- 移开再摆手可触发下一次；不确定分类不解锁。
- 旧帧、断线恢复、新session均不会带着旧候选自动下单。
- 取消核对/退出保留或清除购物车符合页面约定；模拟订单保存失败可见。

参考 [状态机实现](../../src/project/software/laptop/order_core.py)、[传输状态](../../src/project/software/laptop/remote_client.py)、[主机回归说明](../../src/project/docs/host_tests.md)。当前默认2次新结果、保持/释放0.35秒、分数0.60、最大年龄1.5秒仅是本演示配置。通过主机替身测试不等于已验证真实空画面拒识。
