# 网页预览与识别延迟

首先询问或测量“卡”的对象：预览掉帧、标签更新慢、手移开仍显示旧结果，还是菜单动作慢。它们可能对应不同瓶颈。

1. 为每次观察保留session/seq/源帧年龄，并分别记录采集Hz、检测/分类耗时、分类调用Hz、输出间隔和预览FPS。无手时条件分类减少，不应把循环Hz与分类Hz混用。
2. 比较关闭/打开预览时同一推理路径的计时，记录编码尺寸、质量、码率和HTTP耗时。控制JSON与预览传输独立，避免图片拖慢控制轮询。
3. 检查队列和锁：采集最新帧、推理输出和编码不能无限积压；大图编码/网络发送不长时间占住共享状态锁。新方案必须同时观察P95年龄和吞吐。
4. 控制动作仅处理新seq；HTTP轮询次数和浏览器刷新次数不是新识别次数。跨会话重置序列状态，过期/断线锁定交互。
5. 两端 monotonic 不可直接相减。本项目以板端age_seconds加本地HTTP耗时保守估计年龄；这不是精确网络单向延迟。
6. 依次试验预览尺寸/质量、限频、后台线程数和显示方式，一次改变一个因素，保留原配置。不要为了提高FPS增加导致结果更旧的流水线。
