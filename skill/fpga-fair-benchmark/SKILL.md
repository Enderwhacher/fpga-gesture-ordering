# 公平测量 PS/PL 收益

先确定问题是“整个版本改善多少”还是“PL本身贡献多少”。前者可跨版本，后者必须有匹配配置的CPU控制组；两种结论不要合并。

1. 核对模型、预处理、固定图、参数、后处理、线程数、后台预览、运行库和硬件身份。同一张图并不自动意味着配置匹配。
2. 先通过数值对照，再预热、重复采样；交替/反向执行候选，保存逐次数据及失败记录。报告样本数、中位数和尾延迟/波动，不只取最好一次。
3. 分层报告核内计算、完整FPGA调用（含传输/同步/复制）、完整网络、检测加分类、源图到结果、输出间隔、采集和显示。参数初始化是否计入单列。
4. 加速比=T_CPU/T_candidate，耗时降幅=(T_CPU-T_candidate)/T_CPU。不能把局部加速比或显示FPS当整机收益；不同口径不计算比值。
5. 若差异与波动相当，结论写为收益有限或尚不稳健；没有原始样本时不能宣称统计显著。新的线程/调度优化需另列贡献。
6. 资源用最终实现报告；HLS估算、仿真和板测分别标注。保留拒绝候选的依据，避免只汇报成功路线。

## 本项目的关键例子

历史图中第二版470.46ms到第四版302.50ms是版本整体比较；同配置CPU305.84ms到协同302.50ms仅约1.09%耗时降低，约1.011倍。后者也需结合逐次波动判断，不能称35.7%都是FPGA带来的。
