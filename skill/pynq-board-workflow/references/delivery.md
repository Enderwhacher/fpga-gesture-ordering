# 可复现交付

交付目录应能区分运行代码、构建源码、bit/hwh、模型/参数、依赖、测试向量、实测报告和启动入口。说明哪些是可直接部署工件，哪些需重新构建。

记录 SHA 和版本，不靠“final/new”文件名选择候选。源码改动应生成新的候选清单，不重写历史证据。Notebook 输出和运行日志属于可变数据；不要为了允许其变化而关闭所有源码校验。

性能记录区分局部核、完整网络、检测加分类、采集到结果年龄、结果间隔和预览 FPS。比较相同输入、线程配置和后台负载，并保留每次样本；等待参数加载是否计入要明示。

主机 mock、C 仿真、RTL 仿真、实现时序通过和真实板测是不同证据层。资源来自 HLS 估算还是最终实现报告要注明；不从一个正 slack 推导未经验证的更高 Fmax。

做体积受限提交包时可移除生成缓存和重复安装档，但保留构建入口与被排除清单。源码摘录没有 routed DCP 就不能宣称可直接查看原实现结果。解压复核清单后再发布，原完整版本独立保留。
