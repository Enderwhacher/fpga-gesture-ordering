# 相机、显示与网络

USB 摄像头先独立测试打开、读帧、格式、实际吞吐和失败次数。设备声明的 FPS 不等于实际读帧速度；记录请求格式与驱动读回格式。MJPG 可作为候选对比，也要计入解码开销，不假定任何相机都支持。

采集、推理、预览各自计时。交互通常需要最新帧，可用有界最新帧槽，避免无界队列积压；帧附带序号和采集时间，结果关联同一源帧。预览快不代表推理快。

HDMI 是否可用取决于当前 Overlay、板载接口、驱动和显示模式。板卡自带 base 能显示，不证明自定义完整 bit 里也有视频电路。释放视频 buffer 与停止输出使用当前板卡库的 API，不跨平台照抄。

笔记本网页方案通过网络传送状态或预览，笔记本再 HDMI 输出；通常不需要板卡到笔记本的 HDMI 线。USB Composite 只有在两端实际枚举出网络接口并配置可达地址时才能承载 HTTP，不能仅凭插线或接口名称判断联网。先看已有连接/IP，再测试项目服务，避免无关端口扫描或改全网配置。

网络调试逐层区分：IP 可达、端口监听、HTTP 响应、JSON 协议、前端绘制。服务绑定地址、客户端目标和防火墙作用不同；连接拒绝不一定是网络故障。

预览与控制结果使用独立通道/预算，不要把大图片塞进每次控制轮询。动作只能由新的、未过期的识别结果触发。两台机器的 monotonic 时间无共同零点，使用源端报告年龄和本地 HTTP 耗时估计新鲜度。
