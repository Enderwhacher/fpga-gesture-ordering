# 按现象定位

| 现象 | 先检查 | 不应直接做 |
|---|---|---|
| import 成功但 Notebook 找不到模型 | 内核解释器、工作目录、绝对模型路径、缺失文件清单 | 重装板卡镜像 |
| IP 属性不存在或驱动未绑定 | 当前 hwh 的层级/IP类型、PYNQ 版本、对应 bit | 猜一个 MMIO 地址 |
| 加载后首次寄存器访问挂起 | PS 参数、时钟、reset 极性、控制互连、供电与原始日志 | 不断重复读同一失联地址 |
| DMA 不完成 | IP 是否启动、S2MM 是否准备、TLAST、长度、错误状态、缓存责任 | 无限 wait 或仍活跃时 free buffer |
| 首次正确后续错 | buffer 所有权、参数是否丢失、事务重叠、状态清除、缓存 | 只增加延时掩盖竞争 |
| 加速 bit 运行后 HDMI 黑屏 | 新设计是否含视频链路、是否替换了 base | 再加载 base 并期望加速核仍在 |
| 相机无新帧 | 是否被旧进程占用、格式、设备号、读取错误、线程状态 | 只把超时从 3 秒改为无限 |
| 网页卡但板上模型计时正常 | 编码、传输、队列年龄、HTTP RTT、前端绘制 | 先改 HLS 并行度 |
| 局部核变快整机没改善 | 核占比、传输/复制、CPU剩余阶段、后台争抢 | 把局部加速比写成整机加速比 |

恢复要区分 Python 错误、驱动状态异常和硬件死锁。一次受控尝试失败后先保存证据并重新定位；相同死锁不持续自动重试。设备重启、Overlay 重载和内核重启各自影响不同，不互相替代。
